Done — same face pair now means one road, not two routes. It's in the build above.

How it works now: every run between the same pair of faces gets grouped into a bank. The solver routes one centreline per bank, then draws each run as a parallel lane offset from it at your latSpace centres. So the LV and FIBRE in the test case both take the same 45° step-under around the obstacle, side by side, instead of inventing two different paths. Different levels stack on the same centreline in plan, and a pending run you haven't placed yet previews in its lane alongside the placed ones — just verified that case before shipping.

The bank routes to the strictest combination of its members' specs: largest bend radius (grown by the outermost lane's offset so the outside duct still makes the sweep), widest buffer, tightest warning angle, and only bend angles every member's spec allows. Bank-vs-bank clearance and face-width checks run on the whole group, so an overcrowded face flags every run on it.

One thing you'll see: on short stubs the outer lanes can throw amber radius warnings where a bend tangent gets cut — that's real, not a glitch. Widening the stub length or the face gives it room and the amber clears. Related change under the hood: the solver now scores those cuts instead of refusing them, so marginal geometry shows you an honest tight bend rather than detouring into something ugly to stay "legal".
