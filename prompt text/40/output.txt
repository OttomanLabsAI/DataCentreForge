Version 40: conduit runs get their encasement boxes.

Every conduit spec now carries an encasement offset, in the spec's Spacing, clearance and encasement cluster, and the MV spec has 100 mm from the start; the others have none until given one. A run on a spec with an offset wears an encasement box: a rectangle that far beyond the conduits' outer diameter, as wide as the array's widest row and as high as all its rows together, so a 3 over 2 MV array at the tool's spacing gets a box 1,600 wide by 700 high. The plan draws it as a shaded band along the run with its two edges dashed, the elevation draws the box round the array on the face, the 3D view draws the box's four long edges, the run's Route cluster names its size, and the drawing's file carries the offset on the spec and the box on every run. The box also counts: runs keep their clearance from each other's boxes rather than their conduits, the keep-outs round obstacles and the ground cover allow for it, and a run pushed close to an encased neighbour is held further off by both boxes. Set the offset to zero and the box goes.

Verified in a driven browser: the MV spec starting with 100 and the others with none; a 3 over 2 MV run measuring its box as the three conduits wide and the two rows high, 100 beyond each side; the plan drawing the band and both edges; the elevation drawing the box at true scale; the 3D view giving four edges at the box's top, bottom and full width; the panel naming 1,600 wide by 700 high; the spec editor's field reading 100 and, set to zero, taking the box off the run and the plan; two MV banks keeping 1,000 between centrelines instead of 800; and the export carrying the offset and the box, plus the batteries from versions 14 to 39, all passing with no console errors. One check from version 20 humped an MV run over an obstacle 900 below ground with no cover asked; with the box now standing 100 beyond the conduits that hump would break the surface, which is the intended refusal, so the check's obstacle sits 200 lower.
